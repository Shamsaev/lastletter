# Last Letter — дизайн игры

Цепочка слов для Discord Activity. Минимум интерфейса, максимум понятности.

## Правила (как видит игрок)

1. От 2 игроков. Порядок ходов случайный, по кругу.
2. В начале круга один игрок **выбирает букву**. Следующий по кругу пишет английское слово на эту букву.
3. Дальше каждый пишет слово на **последнюю букву** предыдущего слова.
4. Слово нельзя повторять (в пределах всей партии). Минимум 3 буквы.
5. Не успел за время хода — **−1 ❤️** (всего 3). После этого новый круг начинает он: выбирает букву.
6. 0 ❤️ — выбыл. Последний живой — победитель.
7. 15 секунд на ход (можно 10 / 20 в лобби), время не уменьшается.
8. Правила — только по кнопке **!**; в интерфейсе нет текстовых подсказок.

## Решения и почему

| Вопрос | Выбор | За | Против / риск |
|---|---|---|---|
| Где живёт логика | **Сервер — единственный источник правды** | Нельзя читерить, один таймер на всех, переподключение не ломает партию | Нужен хостинг с WebSocket (Vercel не подходит) |
| Хостинг | **Node + `ws` в Docker** (VPS / любой хост с WebSocket) | Прозрачно, переносимо, легко тестировать, ничего не прячет | Нужно поднять сервер. Альтернатива: Cloudflare Durable Objects — бесплатно, но завязка на CF API |
| Неверное слово | **Не наказывается**, можно пробовать ещё, пока идёт таймер | Совпадает с правилом «ничего не написал → −❤️», опечатка не убивает | Можно «перебирать» — ограничено частотой отправки (4/сек) и таймером |
| Проверка слов | Локальный словарь ~274k слов (`word-list`, MIT) | Мгновенно, без внешних API и лимитов | Принимает редкие слова и формы (cats, ran). Для дружеской игры это плюс |
| Повторы | Запрещены на **всю партию** | Игра сама усложняется со временем | — |
| Таймер хода | 15 с по умолчанию (10 / 20 в лобби), **без ускорения** | Предсказуемо, честно для медленных | Партия может затянуться — её укорачивают повторы слов, которые запрещены на всю партию |
| Выбор буквы | 10 с; не выбрал — случайная частая буква, **без штрафа** | Никто не застрянет, не обидно | — |
| Кто отвечает на выбранную букву | Следующий живой после выбравшего | Как в правилах; выбравший не отвечает сам себе | — |
| Хост | **Нет хоста**: начать может любой, нужно ≥2 игроков | Нет проблемы «хост вышел» | Кто-то может нажать «Старт» рано — для друзей ок |
| Пришёл во время партии | Зритель, видит игру, автоматически играет в следующей | Ничего не ломается | Ждать конца партии |
| Отключился | 20 с на возвращение, потом выбывает. Пока его нет, его таймер идёт | Перезагрузка iframe не убивает | — |
| Ввод | Одно большое поле по центру, автофокус, Enter | Ноль лишних кликов | — |
| Подсказки | **Нет.** Правила за кнопкой «!». Текст ошибки появляется только после Enter (почему слово не принято). Первая буква красная, если не та | Чистый экран | Новичку нужно один раз открыть «!» |
| Русская раскладка | Набор «фззду» автоматически становится «apple» | Главная боль русских игроков — забыть переключить раскладку | — |
| Зрители | Видят, что печатает текущий игрок, в реальном времени | Смотреть интересно, понятно, чей ход | Немного трафика (троттлинг 10/с) |
| Язык интерфейса | ru / en по локали Discord | Для смешанных компаний | — |
| Статистика | **Не в приложении**, а в текстовом чате голосового канала: бот пишет итог каждой партии и раз в день (23:59 МСК) — статистику за всё время по серверу | Экран игры не перегружен, история остаётся в Discord | Нужен бот-токен и право писать в канал |
| Хранение статистики | JSON-файл (`data/stats.json`), атомарная запись | Ноль зависимостей, легко бэкапить | Для тысяч серверов понадобится БД |
| Какой канал | Сервер спрашивает Discord `activity-instances/{id}` → `location.channel_id` | Клиент не может подсунуть чужой канал | Фолбэк на `channelId` из SDK, если API недоступен |
| Звук | Короткие сигналы (твой ход, тик последних 3 с, ошибка, −❤️), кнопка mute | Можно не смотреть на экран, пока ждёшь | — |

## Состояния партии

```
lobby ──start──▶ picking ──pick / таймаут(случайная буква)──▶ typing
                    ▲                                        │  │
                    │          верное слово → следующий игрок ┘  │
                    └──── таймаут: −❤️, он выбирает букву ◀──────┘
                                    │
                       живых ≤ 1 ──▶ over ──▶ «Играть снова» / «Лобби»
```

## Архитектура

```
src/shared/   game.ts      — чистая логика (без IO, время и random передаются снаружи) → юнит-тесты
              protocol.ts  — сообщения клиент ⇄ сервер
              text.ts      — нормализация, раскладка, валидация символов
src/server/   index.ts     — HTTP (статика + /api/token) + WebSocket /ws, комнаты по Discord instanceId
              stats.ts     — статистика, сообщение после партии, дневная сводка (с догоном после рестарта)
              dictionary.ts
src/client/   React + Vite, Discord Embedded App SDK; вне Discord — режим браузера (?name=&room=)
```

Комната = `instanceId` активности, т.е. все, кто в одном войсе открыл активность, играют вместе.
Сервер шлёт полное состояние после каждого изменения (оно маленькое) — без диффов, без рассинхрона.
Таймер на клиенте рисуется от серверного `deadline` с поправкой на разницу часов.
